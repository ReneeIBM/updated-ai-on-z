Optimize Model

Once a model has been trained, it often needs to be converted and prepared before it can be deployed efficiently on IBM Z. This stage is about making your model portable, hardware-aware, and ready for production — converting it into the right format, compiling it for Telum AI acceleration, and tuning for the throughput and latency targets your workload demands.

For many teams this stage is short — convert to ONNX or PMML and move to deploy. For others working on deep learning models or LLMs, compilation with the IBM Z Deep Learning Compiler and quantization with AI Optimizer can significantly improve performance on Telum I and Telum II hardware.

What happens at this stage?

Convert to a portable format

Export your trained model to ONNX (deep learning) or PMML (traditional ML) — standard interchange formats that work across Z operating systems and deployment tools.

Compile for Telum acceleration

Use the IBM Z Deep Learning Compiler to compile ONNX models into optimized s390x binaries that automatically offload eligible operations to the Telum AI accelerator.

Quantize for performance

Apply INT8 quantization to reduce model size and inference latency. Telum II on IBM z17 natively supports INT8, delivering up to 2x the speed and memory efficiency of FP16.

Validate before deployment

Check that operation targets are correct — which ops run on the AI accelerator vs. CPU — and profile model performance before moving to production.

Who is this stage for?

Optimization is primarily owned by Data Scientists and ML Engineers working together. The Data Scientist knows the model and acceptable accuracy trade-offs; the ML Engineer handles the compilation pipeline and deployment tooling. IT Architects are stakeholders when hardware acceleration and infrastructure decisions are involved.

ONNX: The Model Interchange Format

ONNX (Open Neural Network Exchange) is the standard portable format for representing deep learning and machine learning models. It allows you to build and train using the framework of your choice — TensorFlow, PyTorch, or others — then deploy the model anywhere, including IBM Z.

Why ONNX matters for IBM Z

  • Framework portability — Build and train on any platform or framework, deploy on IBM Z without being locked to that framework at runtime.
  • Cross-OS compatibility — An ONNX model can be deployed on z/OS (via MLz or zCX), Linux on Z, and LinuxONE from the same artifact.
  • Hardware acceleration — The IBM Z Deep Learning Compiler compiles ONNX models to exploit the IBM Integrated Accelerator for AI on Telum I and Telum II.
  • Ecosystem interoperability — ONNX models can be explored with tools like Netron and served via Triton Inference Server.

Best practice: Convert to ONNX on the platform where the model was trained to avoid endian issues — convert on x86 before transferring to IBM Z or LinuxONE.

PMML: Portable Traditional ML Models

PMML (Predictive Model Markup Language) is the standard portable format for traditional machine learning models — linear models, decision trees, random forests, gradient boosting machines, and SVMs. It is the primary deployment format for traditional ML models on IBM Z, supported natively by both Machine Learning for z/OS and IBM Snap ML.

Why PMML on IBM Z

  • Machine Learning for z/OS deploys PMML models directly with full scoring integration into CICS, IMS, and Java applications
  • IBM Snap ML can exploit the IBM Integrated Accelerator for AI for PMML-formatted tree-based models (Random Forest, Extra Trees, GBM)
  • Decouples the training environment from the deployment environment — train in Python, deploy on z/OS

How to convert to PMML

The recommended approach is the sklearn2pmml library, which wraps scikit-learn, XGBoost, and LightGBM models in a PMMLPipeline for export:

from sklearn2pmml import PMMLPipeline, sklearn2pmml
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(n_estimators=200, max_depth=6)
pipeline = PMMLPipeline([("model", model)]).fit(X_train, y_train)
sklearn2pmml(pipeline, "model.pmml", with_repr=True)

SnapML-trained models can also be exported directly to PMML since v1.9.1, removing the sklearn2pmml dependency for those model types.

IBM Z Deep Learning Compiler (zDLC)

The IBM Z Deep Learning Compiler (zDLC) compiles ONNX models into optimized s390x binaries that exploit the IBM Integrated Accelerator for AI on Telum I and Telum II processors. It is based on the open-source ONNX-MLIR project, with IBM Research enhancements to target the Telum AI accelerator — contributions that have been upstreamed to ONNX-MLIR.

What zDLC does

  • Takes an ONNX model as input and produces a lightweight .so shared library with no framework dependencies
  • Automatically identifies and offloads eligible operations to the Telum on-chip AI accelerator via zDNN — no manual mapping required
  • Falls back to CPU for operators not yet supported on the accelerator
  • The compiled library can be embedded in applications or served via Triton Inference Server
  • Supports C++, Java, and Python APIs for application integration

Extended support in 2025

  • Compiles encoder LLMs for Telum II acceleration
  • Supports a set of small decoder LLMs (up to 2B parameters) for deployment on IBM z17 and LinuxONE 5
  • Updated ONNX-MLIR support for Telum II (IBM z17) new operations: INT8 quantization, Layer Normalization, Gelu, and more

INT8 quantization on Telum II

The IBM z17 Telum II processor natively supports INT8 quantization, designed to reduce inference latency compared to non-quantized models. INT8 quantization reduces and stores weights and activations from 32-bit floating point to 8-bit integers — enabling faster computation at lower memory usage.

  • INT8 is up to 2x more efficient than FP16 in speed and memory usage
  • IBM z17 can process up to 450 billion inference operations per day with 1ms response time using a credit card fraud detection deep learning model
  • 83% energy reduction for AI inferencing on IBM z17 versus comparable x86 with GPU
