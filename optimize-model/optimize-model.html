Optimize Model

Once a model has been trained, it often needs to be converted and prepared before it can be deployed efficiently on IBM Z. This stage is about making your model portable, hardware-aware, and ready for production — converting it into the right format, compiling it for Telum AI acceleration, and tuning for the throughput and latency targets your workload demands.

For many teams this stage is short — convert to ONNX or PMML and move to deploy. For others working on deep learning models or LLMs, compilation with the IBM Z Deep Learning Compiler and quantization with AI Optimizer can significantly improve performance on Telum I and Telum II hardware.

What happens at this stage?

Convert to a portable format

Export your trained model to ONNX (deep learning) or PMML (traditional ML) — standard interchange formats that work across Z operating systems and deployment tools.

Compile for Telum acceleration

Use the IBM Z Deep Learning Compiler to compile ONNX models into optimized s390x binaries that automatically offload eligible operations to the Telum AI accelerator.

Quantize for performance

Apply INT8 quantization to reduce model size and inference latency. Telum II on IBM z17 natively supports INT8, delivering up to 2x the speed and memory efficiency of FP16.

Validate before deployment

Check that operation targets are correct — which ops run on the AI accelerator vs. CPU — and profile model performance before moving to production.

Who is this stage for?

Optimization is primarily owned by Data Scientists and ML Engineers working together. The Data Scientist knows the model and acceptable accuracy trade-offs; the ML Engineer handles the compilation pipeline and deployment tooling. IT Architects are stakeholders when hardware acceleration and infrastructure decisions are involved.

Where to Start

Your path through this stage depends on your model type and target deployment environment. Use this to find your path:

Traditional ML model — scikit-learn, XGBoost, LightGBM

You trained a random forest, gradient boosting, or linear model and need to get it into a deployable format for IBM Z.

→ Convert to PMML using sklearn2pmml. Machine Learning for z/OS and IBM Snap ML both support PMML natively. SnapML-trained tree models (Random Forest, Extra Trees, GBM) can be exported to PMML directly since v1.9.1.

Deep learning model — TensorFlow, PyTorch

You trained a neural network and want to deploy it on IBM Z with Telum AI acceleration.

→ Export to ONNX, then compile with the IBM Z Deep Learning Compiler (zDLC). The compiler produces an optimized s390x binary that automatically offloads eligible operations to the Integrated Accelerator for AI.

Improving performance for production

Your model is already deployed or compiling, but you need to hit tighter latency or throughput SLAs in production.

→ Use AI Optimizer for IBM Z and LinuxONE. It provides quantization (INT8/FP16), model routing, and an all-in-one inferencing stack with real-time observability — designed to maximize Telum II and Spyre acceleration.

LLMs and encoder models for Spyre

You're deploying a large language model or encoder LLM for generative AI use cases on IBM z17 with Spyre acceleration.

→ The IBM Z Deep Learning Compiler now supports encoder LLMs and a set of small decoder LLMs (up to 2B parameters). Combine with AI Optimizer for a pre-validated inferencing stack on Spyre.
