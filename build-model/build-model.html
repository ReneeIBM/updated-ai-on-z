Build Models

This stage focuses on developing the models that power AI applications. Activities may include building traditional machine learning or deep learning models, selecting a foundation model, or fine-tuning a large language model. IBM Z supports many of the tools and frameworks commonly used by AI practitioners, with hardware acceleration available through the Telum on-chip AI accelerator for supported workloads.

Model development does not need to occur on IBM Z. Many organizations develop and train models in cloud or hybrid environments before deploying them to IBM Z for production inference. IBM Z can also serve as a model development platform, allowing organizations to keep data, model development, deployment, and inference within the same environment.

What happens at this stage?

Build traditional ML models

Train classification, regression, forecasting, or recommendation models on structured enterprise data using tools like Snap ML, Spark MLlib, Python AI Toolkit, or Machine Learning for IBM z/OS.

Build deep learning models

Develop neural networks for computer vision, NLP, or other unstructured data workloads using TensorFlow or PyTorch, optimized for IBM Z hardware.

Use and tune large language models

Source a pre-existing LLM from a provider like Hugging Face, then use it as-is, fine-tune it with your own documents, or apply prompt engineering — without training from scratch.

Export for deployment

Save your model in a portable format — PMML for traditional ML, ONNX for deep learning — ready for the deploy and serve stages.

Who is this stage for?

Model development is typically led by Data Scientists, with ML Engineers supporting training pipelines, automation, and operationalization. IT Architects and Application Architects often help evaluate platforms, frameworks, and deployment requirements. Business stakeholders provide domain expertise and help define success criteria, such as model performance goals and acceptable accuracy thresholds.

Where to Start

Your starting point depends on the type of model you're building. The three paths below reflect how IBM Z typically supports the spectrum of model types.

Building Traditional Machine Learning Models

You are working with structured or tabular data and need models such as classification, regression, or forecasting systems.

You need to train classical ML models on IBM Z using a library optimized for the platform.

→ Use IBM Z Accelerated SnapML. Snap ML is the primary training technology for traditional ML on IBM Z, supporting classification and regression models. Decision tree ensemble inference is optimized on the Telum on-chip AI accelerator. IBM Z Accelerated SnapML is available as a container through the AI Toolkit for IBM Z and IBM LinuxONE via the IBM Container Registry (ICR).

Common approach: Prepare features → Train with Snap ML → Export to PMML → Deploy via Machine Learning for IBM z/OS (MLz) or AI Toolkit.

You prefer Python and want to train models using familiar libraries such as scikit-learn, XGBoost, pandas, and NumPy, running natively on z/OS.

→ Use the Python AI Toolkit for IBM z/OS. Provides a curated Python runtime with data science libraries that run natively on z/OS, close to enterprise data sources. Available as a container through the AI Toolkit for IBM Z and IBM LinuxONE via the IBM Container Registry (ICR).

Common approach: Explore data in Jupyter Notebooks → Train with scikit-learn or XGBoost → Export to PMML → Deploy.

Your data is already being processed in Apache Spark, and you want machine learning integrated directly into existing data engineering workflows.

→ Use Apache Spark MLlib via the IBM Z Platform for Apache Spark. MLlib provides scalable ML capabilities that operate within Spark pipelines on IBM Z.

Common approach: Process data in Spark → Engineer features → Train with MLlib → Export and deploy the trained model.

You want model development, training, management, and scoring integrated directly into the z/OS environment without containerization.

→ Use Machine Learning for IBM z/OS (MLz). MLz provides a z/OS-native environment covering the full lifecycle — from training in Jupyter Notebooks to deploying scoring endpoints. MLz also includes explainability features, such as pre- and post-processing support, to help build trustworthy AI models.

Common approach: Develop and train models in MLz Jupyter Notebooks → Deploy using MLz → Expose as scoring endpoints (CICS, IMS, REST API, or batch) for z/OS applications.

Building Deep Learning Models

You need to develop neural networks for computer vision, natural language processing, or other unstructured data workloads. Deep learning models are trained with TensorFlow or PyTorch and typically exported to ONNX for deployment.

You are building deep learning models using TensorFlow or PyTorch and want to train and deploy natively on IBM Z.

→ Use IBM Z Accelerated for TensorFlow or IBM Z Accelerated for PyTorch. Both frameworks are optimized for IBM Z hardware and generate models that leverage the on-chip AI accelerator on Telum and Telum II for inference. Both are available as containers through the AI Toolkit for IBM Z and IBM LinuxONE via the IBM Container Registry (ICR).

Common approach: Prepare data → Train with TensorFlow or PyTorch → Deploy directly via Triton Inference Server or Red Hat OpenShift AI.

Note: Native TensorFlow and PyTorch models cannot be imported into Machine Learning for IBM z/OS (MLz). Use the ONNX path below if deploying to MLz.

You are using any deep learning framework — Keras, PyTorch, TensorFlow, or others — and want to convert your model to ONNX for deployment on IBM Z.

→ Convert your model to ONNX format using your framework of choice, then deploy to IBM Z. To ensure the model leverages the on-chip AI accelerator on Telum and Telum II for inference, it must be optimized using the IBM Z Deep Learning Compiler (zDLC). The zDLC is available as a container through the AI Toolkit for IBM Z and IBM LinuxONE via the IBM Container Registry (ICR).

Common approach: Train with Keras, PyTorch, TensorFlow, or another framework → Export to ONNX → then:

  • Deploying to Triton Inference Server or Red Hat OpenShift AI: explicitly compile with the IBM Z Deep Learning Compiler (zDLC) before deploying.
  • Deploying to MLz: the Deep Learning Compiler is invoked automatically when you import the model — no manual compile step required.

Multiple teams need shared workspaces, automated pipelines, and AI capabilities using deep learning models.

→ Use Red Hat OpenShift AI. Provides data science workbenches, Kubeflow pipelines, and model lifecycle management on Linux on IBM Z. If your organization already uses OpenShift on distributed or x86 platforms, those same skills and workflows carry over directly to IBM Z — the OpenShift experience is consistent regardless of the underlying platform.

Common approach: Create shared projects → Train TensorFlow or PyTorch models → Promote through OpenShift pipelines → Deploy on IBM Z.

Using and Tuning Large Language Models

Large language models can be sourced from IBM, open source communities, or commercial providers and then deployed directly or adapted for specific use cases. IBM Z supports serving foundation models, fine-tuning them with enterprise data, and shaping model behavior.

Your use case is well-served by a general-purpose LLM without any customization.

→ Use Red Hat AI Inference Server (for Spyre-accelerated decoder LLMs) or Red Hat OpenShift AI (for broader model management and serving on IBM Z) to serve a pre-built LLM sourced from Hugging Face or an IBM model repository. No fine-tuning, training, or ONNX conversion is required — LLMs are served natively by both platforms.

Note: Red Hat AI Inference Server runs standalone and does not require Red Hat OpenShift. Red Hat OpenShift AI is the better fit if your organization already has an OpenShift container strategy.

Common approach: Select a model from Hugging Face or an IBM repository → Serve via Red Hat AI Inference Server or Red Hat OpenShift AI on IBM Z → Integrate with your application.

You have domain-specific documents, transaction records, or internal knowledge you want the model to learn from.

→ Use Red Hat OpenShift AI to fine-tune a pre-existing LLM with your own unstructured text data. Red Hat OpenShift AI provides fine-tuning pipelines and shared workspaces for model customization on IBM Z. Fine-tuning adjusts model weights using your data without training from scratch, saving significant time and resources compared to building and training a model from the ground up.

Note: Red Hat OpenShift AI is the better fit if your organization already has an OpenShift container strategy. The fine-tuned model can then be served via Red Hat OpenShift AI or Red Hat AI Inference Server, which runs standalone outside of OpenShift.

Common approach: Source a base LLM from Hugging Face or an IBM repository → Fine-tune using Red Hat OpenShift AI → Deploy the fine-tuned model via Red Hat OpenShift AI or Red Hat AI Inference Server.

You want to shape how the LLM responds to specific questions or tasks without modifying model weights.

→ Use watsonx.ai to design and test prompts using techniques such as few-shot prompting, chain-of-thought, or retrieval-augmented generation (RAG). The watsonx.ai prompt lab can be used in combination with models deployed on IBM Z via Red Hat OpenShift AI or Red Hat AI Inference Server.

Common approach: Design and test prompts in the watsonx.ai prompt lab → Connect to a model deployed on IBM Z → Iterate based on output quality.
