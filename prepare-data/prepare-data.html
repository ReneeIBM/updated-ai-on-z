Prepare Data

Before a model can be trained, data must be cleaned, transformed, and structured for machine learning. On IBM Z, much of the enterprise data used for AI already resides in systems such as Db2, IMS, VSAM, and transactional applications.

This page helps you understand the role of data preparation in the AI lifecycle, identify the tools that support different preparation tasks, and determine which technologies fit your data sources, architecture, and AI objectives.

What happens at this stage?

Access & Connect

Connect to enterprise data sources — Db2, IMS, VSAM, flat files — without moving data off-platform.

Cleanse & Validate

Handle missing values, inconsistent formats, duplicates, and outliers so your model trains on reliable data.

Transform & Engineer Features

Aggregate, normalize, encode, and derive new features that give the model meaningful signals to learn from.

Build Pipelines

Automate repeatable preparation steps so data flows consistently from source to model training — and again at inference time.

Who is this stage for?

Data preparation is typically performed by Data Engineers and Data Scientists, with input from business stakeholders who help define data requirements, quality expectations, and desired outcomes. Depending on team structure, responsibilities may range from dedicated data pipelines to end-to-end preparation within notebooks and machine learning workflows.

Where to Start

Your starting point depends on where your data resides, how much preparation is required, and how your team prefers to work.

Starting a POC or Demo

You don't have access to production data yet, or you want to move quickly without data privacy concerns.

→ Start with IBM Synthetic Data Sets. Pre-built, realistic datasets help you build, test, and validate models without waiting for production data access.

Common approach: Use synthetic data to develop and validate a model, then retrain with production data when it becomes available.

Building a Production Data Pipeline

You need to process large volumes of enterprise data, perform complex transformations, or create repeatable feature engineering workflows.

→ Use IBM Z Platform for Apache Spark. Spark runs natively on z/OS and supports large-scale data preparation close to enterprise data sources.

Common approach: Build Spark pipelines that cleanse, transform, and enrich data before supplying it to model training frameworks.

Writing Python-Based Data Preparation Scripts on IBM Z

Your team prefers Python-based workflows and you want to run data preparation scripts directly on z/OS, close to your enterprise data.

→ Use the Python AI Toolkit for IBM Z. This toolkit provides a Python runtime and popular data science libraries (NumPy, pandas, scikit-learn, and more) optimized to run natively on z/OS.

Common approach: Use pandas and scikit-learn pipelines to cleanse, transform, and engineer features from Db2 or VSAM data, keeping all processing on-platform without exporting data to an external environment.

Building a Production AI and MLOps Platform

Multiple teams need shared workspaces, automated pipelines, model management, deployment, and governance across the full AI lifecycle.

→ Use Red Hat OpenShift AI. While Red Hat OpenShift AI supports the full lifecycle on IBM Z, its primary value on this platform is in deployment, inference, and governance — not data preparation. Clients typically prepare data and build models elsewhere, then port them to IBM Z for deployment.

Common approach: Run a Red Hat OpenShift AI instance on x86 or cloud to prepare data and build models, then smoothly deploy to the IBM Z instance for low-latency inference close to enterprise data.

Note: Data preparation is possible within Red Hat OpenShift AI on IBM Z, but this is not the typical scenario. If your goal is primarily data preparation, see the IBM Z Platform for Apache Spark or Python AI Toolkit for IBM Z cards above.

Preparing Historical Data for Model Training (Outside IBM Z)

Your data science team already uses cloud, data lake, or x86-based tooling to prepare historical training data, and you plan to deploy the trained model on IBM Z.

→ Use your existing data preparation tools and export the trained model in a portable format such as Joblib (the standard format for traditional ML pipelines), PMML, or ONNX (for deep learning models).

Common approach: Prepare historical data and train the model externally, then export it in a portable format and deploy it on IBM Z for low-latency inference close to your enterprise transactions.

Note: Preparing data and building models off-platform is a practical approach. However, IBM Z is designed to deliver the greatest value when AI workloads are deployed and served on platform, where models can run close to enterprise data, business applications, and high-volume transactions.
