AI on IBM Z

Prepare Data

Before a model can be trained, your data needs to be in the right shape — cleaned, transformed, and structured in a way the model can learn from. For IBM Z teams, this stage has a distinct advantage: your most valuable enterprise data already lives here, in Db2, IMS, VSAM, and transactional systems. You don't need to move it to prepare it.

This page helps you understand what data preparation looks like on IBM Z, which tools apply to your situation, and how to move forward whether you're building your first proof of concept or preparing a production pipeline.

What happens at this stage?

Access & Connect

Connect to enterprise data sources — Db2, IMS, VSAM, flat files — without moving data off-platform.

Cleanse & Validate

Handle missing values, inconsistent formats, duplicates, and outliers so your model trains on reliable data.

Transform & Engineer Features

Aggregate, normalize, encode, and derive new features that give the model meaningful signals to learn from.

Build Pipelines

Automate repeatable preparation steps so data flows consistently from source to model training — and again at inference time.

Who is this stage for?

Data preparation is primarily owned by Data Engineers and Data Scientists, often working together. Data Owners and Line of Business stakeholders are involved in defining what data is relevant and what the expected values look like. If you're a data scientist who works end-to-end on smaller projects, this stage is still yours — the tools below work for both pipelines and notebooks.

Where to Start

Your starting point depends on what data you have access to and what you're trying to build. Use this to find your path:

Starting a POC or demo

You don't have access to production data yet, or you want to move fast without data privacy concerns.

→ Start with IBM Synthetic Data Sets. Pre-built, realistic financial datasets let you build and validate a model without waiting on data access approvals.

Working with Db2 data on z/OS

Your data lives in Db2 for z/OS and you want to explore it, find patterns, or prepare features without writing a full pipeline.

→ Use IBM SQL Data Insights Pro. Run AI-powered semantic queries directly inside Db2 — no data movement, no pipeline required.

Building a production data pipeline

You need to process large volumes of enterprise data, automate feature engineering, or build repeatable pipelines for model training.

→ Use IBM Z Platform for Apache Spark. Run Spark natively on z/OS to transform and prepare data at scale, co-located with your enterprise systems.

Using Python-based tools

Your team works in Python and you want to use familiar libraries like pandas, scikit-learn, or NumPy on IBM Z data.

→ Use the Python AI Toolkit for z/OS. ~235 Python packages run natively on z/OS, with access to enterprise data in place.

Building a production AI and MLOps platform

You need a collaborative environment for data preparation, model training, pipelines, deployment, and governance across teams.

→ Use Red Hat OpenShift AI. Provides data science workbenches, Kubeflow pipelines, model serving, and MLOps capabilities on a unified platform.

Common Patterns

These are the data preparation patterns most commonly seen in IBM Z AI projects. Most production solutions use a combination of more than one.

PatternWhen to use itTools
In-database preparation Data lives in Db2; you want minimal movement and fast exploration SQL Data Insights Pro, Db2 for z/OS
Spark pipeline on z/OS High-volume data, complex transformations, production-grade pipelines IBM Z Platform for Apache Spark
Python notebook workflow Exploratory data analysis, iterative feature engineering, data science teams Python AI Toolkit for z/OS, pandas, scikit-learn
Synthetic data for POC No production data available; need realistic data to build and demonstrate a model IBM Synthetic Data Sets
MLOps platform Multiple teams need shared workbenches, automated pipelines, governance, and deployment Red Hat OpenShift AI
Hybrid: prepare off-Z, deploy on Z Team uses cloud or x86 tools for preparation; model will be deployed on IBM Z Any ETL/pipeline tool → ONNX or PMML export → IBM Z runtime
