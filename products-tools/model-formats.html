Model Formats & Compilers

Before a model can run on IBM Z, it usually needs to be in the right format. ONNX and PMML are the two main interchange formats, and the IBM Z Deep Learning Compiler converts ONNX models into artifacts optimized for the Telum on-chip accelerator.

ONNX is the Open Neural Network eXchange. You can read more about it here and explore how it is leveraged by the IBM Z Deep Learning Compiler here.

Converting or exporting trained deep learning models to the ONNX format is a requirement for leveraging the IBM Z Deep Learning Compiler, whether stand-alone or as part of Machine Learning for IBM z/OS.

The approach in deep learning frameworks varies - for example:

  • TensorFlow models must be converted using the open-source tensorflow-onnx package.
  • PyTorch models can be exported directly to ONNX using PyTorch APIs.
  • Information on exporting models from other frameworks can be found on the ONNX community page.

Best practices

To avoid endian issues, we strongly recommend converting models to the ONNX format on the platform on which they were trained. (e.g., if a model was trained on an x86 environment, convert the model to ONNX on an x86 environment before transmitting to IBM Z or LinuxONE).

For Deep Learning Compiler usage: to determine which ONNX opset to specify for model conversion, see the following references:

  • NNPA supported opset level
  • CPU supported opset level

On z16 or LinuxONE 4 machines (or later), we recommend using the highest opset level as specified under NNPA operator support. This will generally be the first statement in the NNPA supported opset level file linked above.

PMML is the predictive model markup language. You can read more about it here. Machine learning models converted to the PMML format can be leveraged by IBM Z Accelerated SnapML; as described here, tree based models can utilize the IBM z16 Integrated Accelerator for AI.

Additionally, Machine Learning for IBM z/OS can deploy PMML models.

Generally, the best approach to converting models to PMML is to use sklearn2pmml. This allows the user to create a PMMLPipeline object, which can contain either scikit-learn, xgboost, or lightGBM models as part of a pipeline.

For considerations for using PMML models in Machine Learning for IBM z/OS, see the MLz documentation.

Samples

For an example of converting a scikit-learn model to PMML, see the IBM Z Accelerated SnapML examples; one such example can be found here.

Additionally, here is a brief code snippet showing the process:

# Create a scikit-learn Random Forest Classifier model
model = RandomForestClassifier(n_estimators = 200, max_depth=6, n_jobs=4, random_state=42)

# Train a PMML pipeline that uses the scikit-learn model defined above
pipeline = PMMLPipeline([("model", model)]).fit(X_train, y_train)

# Save the trained PMML pipeline to a file, e.g., "model.pmml"
sklearn2pmml(pipeline, "model.pmml", with_repr=True)

The IBM Z Deep Learning Compiler compiles ONNX models into optimized s390x binaries that automatically offload eligible operations to the Telum on-chip AI accelerator via the zDNN library — no manual mapping required. It is based on the open-source ONNX-MLIR project with IBM Research enhancements contributed upstream.

zDLC is available as part of the AI Toolkit for IBM Z and IBM LinuxONE, distributed through the IBM Z and LinuxONE Container Registry.

Key capabilities

  • Produces a lightweight .so shared library with no framework dependencies at runtime
  • Supports encoder LLMs and small decoder LLMs (up to 2B parameters) on IBM z17 and LinuxONE 5
  • INT8 quantization, Layer Normalization, and GeLU support on Telum II (IBM z17)
  • Embeddable in applications or serveable via Triton Inference Server
  • C++, Java, and Python runtime APIs

Getting started — by platform

z/OS users can use MLz's built-in integration:

  • Machine Learning for IBM z/OS (MLz) — Upload your ONNX model and compile at the push of a button. Supports server-side mini-batching for ONNX/DLC model serving and native CICS, IMS, and Java scoring services.

Linux on Z, zCX, and LinuxONE users can use zDLC directly:

  • Pull the container image from the IBM Z and LinuxONE Container Registry (listed as zDLC)
  • Run the command-line compiler to produce a .so library ready for application embedding or Triton serving

Determining accelerator coverage

When compiling with zDLC, you can inspect which model operations will run on the Telum AI accelerator vs. CPU — critical information for performance analysis:

  • Pass --EmitLib --maccel=NNPA and review the compilation output for op target assignments
  • Enable runtime instrumentation to measure accelerator utilization during inference
  • See the zDLC official documentation for the full list of NNPA-supported ONNX ops and opset levels
